# Robozon - интеллектуальная роботизированная сортировка товаров

Проект для трека 3 хакатона Ozon. Система определяет габариты и форму товара на подающем конвейере, назначает одну из зон B/C/D и передаёт решение исполнительной части для физической маршрутизации.

## Как работает система

```text
фотобарьер / камеры
        |
        v
frames_to_cloud.py  ->  облако точек
        |
        v
cloud_classify.py   ->  габариты + K + категория
        |
        v
pipeline.py         ->  Decision(zone, confidence, grasp)
        |
        v
runtime.py          ->  SHOOT / SEQ / DONE
        |
        v
Arduino + манипулятор -> B напрямую, C/D через буфер
```

Правила применяются строго по приоритету:

1. Если минимальный габарит не больше 10 мм или превышен предел 450x320x320 мм - зона C.
2. Иначе проверяется круг в сечении: `K = r_вписанной / R_описанной`.
3. Круглый товар направляется в D, остальные товары - в B.
4. Пограничный, плохо измеренный или катящийся товар выводится на безопасный ручной разбор и не попадает в основной сортировщик.

## Структура исходного кода

Все Python-файлы находятся в папке `файлы, которыет есть в репозитории на git`.

| Файл | Назначение |
|---|---|
| `frames_to_cloud.py` | вычитание фона, силуэты трёх камер и визуальная оболочка |
| `cloud_classify.py` | рантайм-классификация облака, габариты, K, поза захвата, укатывание |
| `stl_classify.py` | офлайн-разметка STL/OBJ/PLY и экспорт CSV/JSON |
| `virtual_scan.py` | виртуальный верхний сканер STL с шумом и выпадением точек |
| `pipeline.py` | единая точка входа `Vision.process()` и объект `Decision` |
| `runtime (3).py` | многопоточный контур Raspberry Pi и протокол перекладки |
| `arm_kinematics (1).py` | обратная кинематика и траектория pick/lift/drop |
| `link_protocol (1).py` | UART-кодирование, CRC и обмен Raspberry Pi <-> ESP32 |

Суффиксы `(1)` и `(3)` появились при экспорте файлов. Код ожидает канонические имена `arm_kinematics.py`, `runtime.py` и `link_protocol.py`.

## Требования

- Python 3.10+
- `numpy`
- `opencv-python`
- `scipy`
- `shapely>=2.0`
- `trimesh`
- `pyserial` - только для запуска с контроллером

Установка в виртуальное окружение:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install numpy opencv-python scipy "shapely>=2.0" trimesh pyserial
```

## Быстрый запуск без железа

Сначала создайте рабочие копии файлов с каноническими именами:

```bash
cd "файлы, которыет есть в репозитории на git"
cp "arm_kinematics (1).py" arm_kinematics.py
cp "runtime (3).py" runtime.py
cp "link_protocol (1).py" link_protocol.py
python runtime.py --selftest
```

Selftest моделирует четыре случая: обычную коробку B, негабарит C, лежащий цилиндр D и катящийся цилиндр.

Проверка протокола и CRC:

```bash
python link_protocol.py
```

## Проверка на цифровых моделях

Офлайн-классификация набора STL:

```bash
python stl_classify.py --input ./stl --output ./out --step 3 --jobs 4
```

Виртуальный скан только видимой верхней поверхности:

```bash
python virtual_scan.py --input ./stl --res 0.5 --noise 0.3 --dropout 0.02
```

Рантайм-классификация виртуального облака:

```bash
python cloud_classify.py --input ./stl --source hull
```

## Запуск с контроллером

```bash
python runtime.py --port /dev/ttyACM0
```

Перед запуском на стенде обязательно настроить параметры в верхних блоках `arm_kinematics.py` и `runtime.py`:

- длины звеньев, высоту базы и пределы сервоприводов;
- точки pick/lift/drop и смещения систем координат;
- рабочий объём камер и их калиброванные проекции;
- порог уверенности и таймаут `arm_busy`;
- порт Serial.

## Ключевые инженерные решения

- B проходит напрямую в сортировщик: манипулятор обслуживает только C/D.
- Буфер на 5 мест сглаживает кратковременные пачки проблемных товаров.
- Положение товара привязано к энкодеру ведомого вала, а не к времени или оборотам мотора.
- Обратная кинематика проверяет достижимость и обе ветви локтя.
- Arduino использует неблокирующий конечный автомат; Pi разделяет захват, Serial и расчёт на три потока.
- Для визуальной оболочки используется `K=0.87`, для истинной поверхности - `K=0.80`.

## Известные ограничения

- официальный тестовый набор организаторов в репозитории отсутствует;
- взаимная калибровка трёх камер и поправка порога требуют подтверждения на реальном тракте;
- хобби-сервопривод рассчитан только на лёгкие товары; целевая система требует промышленного привода;
- физические E-STOP и ограждение пока описаны как проектные меры;
- видеодемонстрацию и измеренный cycle time необходимо добавить перед сдачей;
- параметры геометрии в текущем `arm_kinematics (1).py` являются калибровочными и должны быть приведены к фактической сборке.
